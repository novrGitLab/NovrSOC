# NovrSOC — Codebase Audit for Video Production

Audit date: 2026-10-27. Scope: identify what in NovrSOC is real/implemented vs. partial/planned,
and extract the real design language (layout, colors, typography, components) so the conference
video reproduces the actual product rather than an invented one.

**Method.** This audit is based on (1) a direct read of `frontend/src/**` and `backend/src/**` in
this repo, and (2) the repo's own prior engineering audit,
[`NOVRSOC_REDESIGN_TECHNICAL_AUDIT_V2.md`](../../NOVRSOC_REDESIGN_TECHNICAL_AUDIT_V2.md) (baseline
`origin/main` at commit `3bd3a6e8`, 1816 lines, generated by reading source + route/table
inventories — not from README claims). Every claim below is either verified directly against
current source in this pass, or cited to that document where it was not independently re-verified
line-by-line. Where the two could conflict, current source wins.

**Hard rule followed:** nothing in this document or the prototype invents a feature, metric,
certification, integration, or customer. All screen data in the Remotion project is synthetic and
is labeled as such on-screen, following the same convention the product itself uses for its own
placeholder data (see [`CloudAssets.tsx:8-21`](../../frontend/src/components/features/CloudAssets.tsx#L8-L21),
which blurs and bannering its AWS preview tab as "example data" while showing real Wazuh agents
plainly).

### Core UI primitives (reuse these exact patterns)
From [`frontend/src/components/features/vms/kit.tsx`](../../frontend/src/components/features/vms/kit.tsx):
- **PageHeader**: icon (purple/`--vz-prog-4`) + bold heading (`text-xl font-black tracking-tight`) + muted description line + right-aligned action buttons.
- **KpiCard**: rounded-2xl card, `--card` background, 1px `--border-default`, tiny muted label on top, large (`text-[26px] font-black tabular-nums`) number below (numbers animate via `CountUp`), optional icon/tone indicator, optional muted sub-line. `null` value renders "Unavailable" with a reason — **real metrics are never silently shown as 0**.
- **Buttons**: `primary` = solid `--brand-purple` with white text; `secondary` = card background with border; rounded-lg, semibold, small (11px) text.
- **SeverityBadge / PriorityBadge / RiskScore**: colored square/dot + label, using the `--vz-sev-*` tokens and `SEVERITY_META` (critical/high/medium/low/info).

## 2. Feature-by-feature implementation status

Status legend: **WORKING** (built, real data, used in nav as such) / **PARTIAL** (built but with
known gaps — still real, not fake) / **NOT PRODUCTION-SAFE** (built but with a serious defect) /
**PLACEHOLDER** (explicitly labeled example data, no real integration) / **MISSING** (not built).
Nav-level status strings (`WORKING`/`PARTIAL`/`BROKEN`) come directly from
[`frontend/src/config/nav.ts`](../../frontend/src/config/nav.ts).

### 2.1 Vulnerability Management System (VMS) — **WORKING**, most mature module
- 23 feature files under `frontend/src/components/features/vms/*`: Dashboard, Asset Management,
  Findings, Risk, Scanning, Schedules, Scope, Services, Endpoints, Remediation(+Plus), Report,
  Audit, Monitor Ops, Attack Surface Map, Client view, Finding Detail.
- Dashboard (`VmsDashboard.tsx`) KPIs, counted from stored records, never estimated: Total assets,
  Open vulnerabilities, Critical vulnerabilities, Critical exposures, Overdue remediation tasks,
  Active scans, New vulnerabilities (period), Remediation completion %, Overall risk score (mean +
  max), Scanner availability (engines online / total).
- Charts: open findings by severity (donut), risk score over time (line, mean+max), new
  vulnerabilities by day/severity, scan activity, status breakdown.
- Lists: recent critical findings, highest-risk assets, active scans, overdue tasks, activity feed.
- Real risk-scoring formula (`backend/src/lib/riskScore.ts`): weighted CVSS (45%) + exploitation via
  KEV/EPSS (30%) + exposure (15%) + asset criticality (10%) → P1–P4 priority with SLA due dates (2/7/30/90 days).
- Real scan engines: Nmap (ports), Nuclei (vuln), subfinder/dnsx/httpx (discovery), Greenbone/OpenVAS
  (present but policy-disabled). Real worker architecture, concurrency limits, retries, heartbeats.
- **P27 scope authorisation**: formal executive sign-off workflow before any active scanning — a
  named organisation declaration, SHA-256-hashed, with approvals, rejections, expiry, revocation.
  This is a genuinely distinctive, demo-worthy "we don't scan without authorisation" feature.
- Gaps (do not claim fixed): risk formula has no per-org versioning yet (global constant); P27
  approval is not transactionally atomic; reporting is JSON + client-rendered PDF (screenshot-based,
  not true text PDF) — no server-side PDF/scheduled delivery yet.
- **Recommended screens for the video:** VMS Dashboard (KPI grid + severity donut + risk trend) is
  the single best "wow" screen in the whole product — use it for the hero progressive-fill animation.

### 2.2 Threat Exposure Management / Threat Intelligence — **WORKING**, real pipeline
- `/admin/ti/*`: Overview, Nigeria Threat Map, Indicators & Investigation, Threat Actors,
  Organisation Matches, Vulnerabilities & Advisories, AI Intelligence Analyst, Sources & Exchange.
- Real indicator store (`ti_indicators`), per-feed provenance, TLP 2.0 marking with enforced
  visibility rules (client roles never see AMBER+STRICT/RED), read-only MISP integration, feed
  health reporting (fetched/new/duplicates/errors).
- External feeds actually wired: Feodo, CIRCL, GreyNoise, IPregistry, RIPEstat, RDAP, crt.sh, NVD,
  KEV, EPSS, OSV.
- Nigeria-specific sourcing is weaker than the rest: ngCERT feed returns 403 to this deployment (no
  data), NITDA arrives only via search-result scraping, no structured NCC-CSIRT/CBN feed yet — the
  Nigerian Threat Feed page explicitly surfaces labeled mock NCC-CSIRT/NGCERT advisory data (per
  `PRODUCTION_NOTES.md` item 8), separate from the real Wazuh-derived Nigeria map.
- **Caution for the video:** the current dashboard's Nigeria "attack" map has a confirmed accuracy
  defect (cumulative re-counting, invented state-level precision from ASN lookups) — the audit
  recommends retiring it in favor of the TI module's map, which correctly distinguishes "hosted
  infrastructure" / "your exposure" / "reported targeting" and only shows state-level precision
  when a provider actually named a state. **Use the TI map's honest precision model, not the
  dashboard map's, if a Nigeria map appears on screen.**

### 2.3 CNII (Critical National Information Infrastructure) Monitoring — **PARTIAL**, real but incomplete
- National → Sector (13 real sectors) → Organisation → Assets → Findings hierarchy exists and
  works. Subsector level is partial (one free-text field per org, no aggregation UI yet).
- Built as an overlay on the same VMS asset/finding model — not a parallel/duplicate system, which
  is architecturally sound and worth showing.
- Risk aggregation currently uses a mean (understates concentrated risk — one P1 among 200 P4s
  reads as low); the audit recommends leading with P1/P2 count and max instead. **If showing a CNII
  risk figure, prefer "open P1/P2 count" framing over an unqualified average.**
- Passive enrichment (no active scanning required) genuinely integrated: SpiderFoot, crt.sh, DNS,
  RIPEstat, OpenCTI.

### 2.4 Security Operations, Alerts & Incident Management — **WORKING** core, **PARTIAL** polish
- Alerts: stored and organisation-scoped, triage workflow, assignment.
- Cases: full CRUD, notes, tasks, escalation, Markdown case reports.
- Response Approvals: pending → approved/rejected workflow for containment actions (block IP,
  isolate host), with self-approval blocked by default and isolation re-checked against agent
  ownership — a real human-in-the-loop control worth featuring.
- MITRE ATT&CK mapping from real Wazuh rule data (shows only 8 of 14 Enterprise tactics currently —
  don't claim full MITRE coverage).
- Gaps: no analyst skills/workload/shift model yet (assignment is manual, stores a name not an id);
  the dashboard's MTTD/MTTR KPI is a hardcoded placeholder ("—") — **do not show an animated MTTD/MTTR
  number**, since no real one exists yet.

### 2.5 AI Security Analyst & SOAR — **WORKING** (AI), **PARTIAL** (SOAR governance)
- Grounded AI service (`services/ai.ts`) with **16 defined purposes**: alert summary, case summary,
  case handover, incident report, finding explanation, remediation plan, rescan interpretation,
  asset assessment, indicator assessment, threat briefing, Nigeria briefing, investigation summary,
  TI question, CNII sector briefing, CNII intake classification, weekly insights.
- Every AI output is schema-validated (zod), evidence-checked against what was actually sent, and
  logged (`ai_requests`) as a draft artifact a human accepts or rejects — not an autonomous action.
  This "draft, never auto-act" model is genuinely good and worth stating explicitly in narration.
- Runs on NVIDIA's hosted API (`nvidia/nemotron-3-super-120b-a12b` by default), with Ollama as a
  self-hosted/data-residency option. **Do not name "Claude"/Anthropic** as the AI provider —
  `PRODUCTION_NOTES.md` explicitly states `ANTHROPIC_API_KEY` is no longer read.
- SOAR engine (`infra/soar/soar.py` on the Wazuh manager) performs real tier-2 (block IP) and
  tier-3 (block + isolate host) automated response — but currently does so **without** going
  through the platform's own Response Approval workflow, a known inconsistency the audit flags for
  remediation. **Do not depict SOAR auto-actions as going through an approval step today** — if the
  video shows an approval workflow, pair it with Response Approvals/Cases (which do work that way),
  not with the raw SOAR block/isolate action.

### 2.6 Email Security & Brand Protection
- **Email Security — WORKING, persistent.** Real tables for domains, phishing domains, messaging
  connections, DMARC. Read access for all staff roles; write for manager/analyst. One real gap:
  no organisation-switching yet (always acts on the viewing staff member's own org) — fine for a
  single-org demo shot, just don't show a staff user switching orgs on this specific screen.
- **Brand Protection — NOT PRODUCTION-SAFE, PARTIAL in nav.** All brand-protection data (monitored
  executives, social accounts, apps, code signatures, brand assets) currently lives in shared
  in-process memory, not scoped per tenant, and is lost on restart. This is a real, known
  engineering gap (`F-01` in the technical audit), not something to hide, but also not something to
  showcase as a flagship capability in a sales video. **Recommendation: feature Email Security
  (DMARC/Phish-ID/Messaging Suite) confidently; touch Brand Protection only lightly/visually (e.g.
  Dark Web Monitor, which is marked WORKING) and avoid narrating specific executive-monitoring
  claims.**

### 2.7 MSSP Multi-tenancy, Reporting, Audit
- Multi-tenant model exists (organisations, roles: `super_admin`, `soc_manager`, `analyst`,
  `executive`, `portal_user`), with per-org data scoping enforced in most — not all — routes.
  **Multitenancy is explicitly "partial"** per `PRODUCTION_NOTES.md` item 6; several routes are not
  yet org-scoped. Fine to depict the *concept* (org switcher, portfolio view, client portal) since
  the UI and data model for it exist; avoid claiming airtight tenant isolation as a finished
  security property.
- Client portal exists (`/client/*`) with working dashboard and VMS pages; several other client
  pages are known-broken today (nav.ts labels 17 client items `BROKEN`) because of an auth-routing
  mismatch. **If showing the client portal, use the Dashboard or VMS client view — not Brand, CTI,
  URL/Web scan, Cases/Alerts, DNS, or Data Recovery client pages.**
- Reporting: real JSON-based VMS/CNII period reports and Markdown case reports exist today;
  client-side PDF export (screenshot-based) exists. A proper server-side PDF/scheduled-report engine
  is planned, not built. Compliance clause mapping (`services/complianceMapping.ts`) is real —
  deterministic references to actual ISO 27001:2022, PCI-DSS v4.0, NDPA 2023, CBN framework clauses,
  explicitly worded as "may bear on," never "compliant/non-compliant." **Good, honest claim to put
  on screen verbatim if compliance is shown.**
- Audit: `audit_log` table with in-memory fallback; Security Assessment / report-card views exist
  for manager+executive roles.

## 4. Reusable component inventory (for the video project)

Rather than importing the live Next.js app's components directly (which would pull in app routing,
data fetching, and auth), the video project **recreates the same visual primitives** as plain
React components driven by static/synthetic data and Remotion's frame-based animation hooks
(`useCurrentFrame`, `interpolate`, `spring`) instead of `useState`/`fetch`. This keeps rendering
deterministic (a hard requirement) while staying visually faithful.

| Real component | Real path | Video project equivalent |
|---|---|---|
| `PageHeader` | `features/vms/kit.tsx` | `src/compositions/shared/PageHeader.tsx` |
| `KpiCard` (+ `CountUp`) | `features/vms/kit.tsx`, `ui.tsx` | `src/compositions/shared/KpiCard.tsx` (frame-driven count-up, not interval-driven) |
| `SeverityBadge` / severity donut | `kit.tsx`, `charts.tsx` | `src/compositions/shared/SeverityDonut.tsx` |
| Sidebar / nav | `components/layout/Sidebar.tsx`, `config/nav.ts` | `src/compositions/shared/Sidebar.tsx` (static icon list, slide-in animation) |
| Dark theme tokens | `app/globals.css` | `src/lib/tokens.ts` (ported as a TS constant object) |
| Fonts | `app/layout.tsx` | `@remotion/google-fonts` loaders for Space Grotesk / Inter / JetBrains Mono |
